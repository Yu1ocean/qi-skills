# stable-frontend-renderer

version: 1.1
把“前端预览”从默认追求高自由度运行时，收敛成“先稳定展示，再逐步放开交互”的执行标准。

默认原则只有一句：**聊天内以稳定展示为先，运行时自由度让位于容器确定性；能编译时解决，就不要运行时解决。**

## Common Rationalizations（常见借口库）

以下说法一旦出现，视为准备绕过稳定性护栏：

- “先把现成 React 页面塞进去看看，能跑就行。”
- “只是预览，不用管第三方依赖和外链脚本。”
- “先直接读取环境变量 / JWT / session，后面再补判空。”
- “只是个聊天卡片，没必要做降级出口。”
- “完整 H5 也能预览，索性统一一条运行时链路。”

## Red Flags（危险信号）

出现任意一条，必须停止默认实现路径，改做收敛或降级：

- 需求本质是“展示”，但实现方案却要运行完整前端工程。
- 代码引入第三方依赖、外链脚本、动态执行或外部样式链路。
- 页面在主渲染链路读取环境变量、Cookie、JWT、sessionStorage 等敏感上下文。
- 计划把已有 H5 直接复用到聊天动态预览容器。
- 交付物没有静态兜底、文档兜底或外链完整版出口。

## Verification（强制验收清单）

当宣称“前端预览方案已稳定”时，至少满足：

1. 已明确归类为 **纯展示 / 轻交互 / 强交互 / 完整 H5** 之一。
2. 已执行 `scripts/render_mode_advisor.py`，并按建议选择主方案。
3. 若涉及已有代码或运行时方案，已执行 `scripts/render_guardrails_check.py`。
4. 没有未解释的高风险项，或已明确给出整改与降级出口。
5. 用户在失败路径下仍能看到结果、说明或跳转，而不是白屏。

## Defaults（合规默认值）

- 聊天场景默认优先：`AUI 官方组件 + 快速预览`
- 纯展示默认优先：`静态 HTML / SVG / 文档嵌入`
- 完整页面复用默认优先：`受控 H5 预览`，不直接并入聊天动态卡片主链路
- 任何非静态方案默认必须提供：`静态快照 / 文档查看 / 外链完整版` 之一作为降级出口

## 何时使用

命中以下任一场景时，优先调用本 skill：

- 用户要求生成 **聊天内前端预览**、**动态 UI**、**可视化看板预览**、**交互卡片**。
- 用户反馈 **白屏**、**脚本被拦截**、**动态预览不稳定**。
- 需要在 **AUI 快速预览**、**动态运行时预览**、**静态 HTML**、**受控 H5 预览** 之间做方案选择。
- 需要把复杂前端页面收敛成 **稳定展示优先** 的交付形式。

## 核心结论

### 1. 优先判断“展示”还是“运行”

- **展示型需求**：图表、结果面板、流程说明、快照、可视化报告。
  - 默认选择：静态 HTML、SVG、飞书文档嵌入、受控展示页。
- **轻交互需求**：单选、多选、少量表单、状态切换、审核确认。
  - 默认选择：AUI 官方组件 + 快速预览。
- **强交互需求**：复杂状态、重运行时、第三方依赖、多个异步源。
  - 默认选择：先评估是否必须；若必须，补齐风险说明与降级出口。
- **完整 H5 复用**：已有成熟页面必须复用。
  - 默认选择：视为单独技术路线，走受控 H5 预览，不混进聊天主链路。

### 2. 默认推荐顺序

1. **AUI 官方组件 + 快速预览**
2. **AUI 轻交互卡片 / 展示型降级**
3. **静态展示 / 文档嵌入 / SVG / 受控 HTML**
4. **受控 H5 预览**
5. **第三方 React 运行时 + 动态预览**（不建议作为默认方案）

### 3. 高风险黑名单

以下做法会显著提高白屏与拦截概率：

- 第三方 React 物料直接进入动态预览容器。
- 外链脚本、非白名单 CDN、inline script。
- `eval`、`new Function`、动态执行。
- 在渲染主链路里裸读环境变量、Cookie、JWT、会话等敏感上下文。
- 外部样式依赖、样式顺序敏感依赖。
- 将完整 H5 页面强塞进聊天容器。

## 标准工作流

### Step 1：判断渲染模式

运行：

```bash
python3 scripts/render_mode_advisor.py --interaction display --chat-scene
```

可选参数：
- `--interaction display|light|medium|heavy`
- `--existing-h5`
- `--needs-runtime`
- `--third-party`
- `--chat-scene`

读取输出 JSON，决定主方案：
- `static_display`
- `aui_quick_preview`
- `controlled_h5_preview`
- `runtime_dynamic_preview`

### Step 2：已有代码时做稳定性扫描

当任务已经存在前端目录、HTML 文件、React 页面，或准备进入运行时链路时，运行：

```bash
python3 scripts/render_guardrails_check.py <file-or-directory>
```

读取风险结果：
- `low`：可继续，但仍需保留降级出口。
- `medium`：补异常边界、空态与静态兜底。
- `high`：优先改回 AUI 官方组件、快速预览或静态展示链路。

### Step 3：选择交付路径

- 需要生成新页面或可视化展示时，**使用 `web-creation` skill 完成页面生成**。
- 需要输出飞书文档承载预览结果时，**使用 `feishu-doc-writing-guide` skill 完成飞书文档创建与写入**。
- 需要图表、流程图、SVG 预览时，可将结果收敛为静态 HTML、SVG 或文档嵌入。

### Step 4：补齐兜底

只要主方案不是纯静态展示，就必须至少补齐：

1. **运行时兜底**：关键参数判空、异常边界、空态提示。
2. **数据兜底**：接口失败时返回空状态或静态示例，不允许整页崩溃。
3. **产品兜底**：提供跳转完整版页面、文档查看或静态快照出口。

## 默认执行规则

### 纯展示
- 默认生成静态 HTML / SVG / 文档嵌入。
- 不主动引入运行时状态管理。

### 轻交互
- 默认使用 AUI 官方组件表达交互。
- 控制状态层级与依赖数量。
- 避免引入业务物料和第三方依赖。

### 强交互
- 不直接假设可以稳定运行。
- 先执行稳定性扫描，再决定是否继续。
- 失败时必须保留降级出口。

### 完整 H5
- 当作“页面预览系统”问题处理。
- 不要与聊天动态卡片混为一谈。

## 最佳实践

### 场景 A：聊天内展示一份可视化分析结果
- 判定为 **纯展示**。
- 优先生成静态 HTML 或飞书文档嵌入结果。
- 不要把它升级成完整 React 运行时。

### 场景 B：聊天内做少量筛选与确认
- 判定为 **轻交互**。
- 优先选择 AUI 官方组件与快速预览。
- 避免第三方组件、外链脚本与复杂状态管理。

### 场景 C：已有 React 页面想直接搬进聊天里
- 先判定是否真的是“必须复用完整页面”。
- 若不是，改造成静态展示或轻交互版本。
- 若是，转成受控 H5 预览路线，并显式告知其不是默认稳定方案。
