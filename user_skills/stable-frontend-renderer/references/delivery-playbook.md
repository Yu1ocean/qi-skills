# 交付执行手册

本文件定义 stable-frontend-renderer 的执行顺序、默认产物与验收标准。

## 1. 先判断需求类型

收到前端预览任务后，先做四分类：

- **纯展示**：图表、结果汇总、流程说明、快照、静态可视化。
- **轻交互**：筛选、确认、少量表单、标签编辑、状态切换。
- **强交互**：复杂状态机、外部依赖、运行时逻辑、多个异步源。
- **完整 H5**：已有页面或网站需要直接预览。

## 2. 默认交付策略

### 纯展示
- 优先生成静态 HTML、文档嵌入、SVG 或图表页面。
- 除非用户明确要求，不进入动态运行时。

### 轻交互
- 优先使用 AUI 官方组件表达交互。
- 尽量减少状态层级与依赖数量。
- 保持编译时可解析，不主动引入第三方运行时。

### 强交互
- 明确告知：该方案不是最稳默认路径。
- 必须运行 `scripts/render_guardrails_check.py` 做风险扫描。
- 必须显式写出降级出口：静态快照、文档、完整版页面。

### 完整 H5
- 作为单独技术路线处理。
- 如果只是“看效果”，优先给静态快照或受控预览，而不是聊天内运行完整应用。

## 3. 最小执行流程

1. 判断是“展示”还是“运行”。
2. 运行 `scripts/render_mode_advisor.py` 获取推荐模式。
3. 若已有代码或计划进入运行时模式，运行 `scripts/render_guardrails_check.py`。
4. 根据建议收敛技术方案。
5. 交付产物前，确认是否提供了降级路径。

## 4. 交付物建议

| 需求类型 | 推荐主交付物 | 备选交付物 |
| --- | --- | --- |
| 纯展示 | 静态 HTML / SVG / 飞书文档嵌入 | 页面截图、图表 HTML |
| 轻交互 | AUI 官方组件页面 | 轻量卡片、表单面板 |
| 强交互 | 受控运行时页面 + 风险说明 + 降级出口 | 完整版外链、静态快照 |
| 完整 H5 | 受控 iframe / 代理预览方案说明 | H5 链接、快照页 |

## 5. 通过标准

交付前至少满足以下条件：

- 已明确归类需求类型。
- 如果引入运行时链路，已明确说明原因。
- 风险扫描结果中不存在未解释的高风险项。
- 核心页面不存在对敏感上下文的裸读。
- 至少存在一种降级出口。
- 用户看到的不是“白屏时啥都没有”，而是可解释、可跳转、可恢复的体验。

## 6. 常见降级模板

### 模板 A：从强交互降到轻交互
将复杂的编辑流程拆成：
- 聊天内仅展示摘要与关键操作按钮。
- 点击后跳转完整版页面处理复杂交互。

### 模板 B：从运行时降到静态展示
将运行中的结果改为：
- 静态图表 HTML。
- SVG 流程图。
- 飞书文档内嵌结果。

### 模板 C：从完整 H5 复用降到受控预览
只保留：
- 关键页面截图。
- 只读预览。
- 关键字段透出。
- 跳转完整版页面。
