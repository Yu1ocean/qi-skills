# 欧洲跨境品牌库·周扫归档技能

## Common Rationalizations（反合理化三件套）

- “文章标题像品牌名，正文没写也先补上”是违规：正文未明确出现的字段必须留空。
- “A/B 列大概率是品牌名列，直接写入”是违规：写入前必须读取表头并按列名定位。
- “公众号链接抓不到，就用转载链接替代”是违规：禁止编造或替换 `mp.weixin.qq.com` 原文链接。

## Red Flags（必须熔断）

- 无法确认目标表头、目标表格 token、或写入列位。
- 新增品牌判断未读取既有品牌名集合（以表头语义定位为准）。
- 任一写入动作绕过 `feishu-doc-writing-guide` 包装器，裸调原生 lark 写入工具。
- 运行摘要缺少扫描篇数、新增品牌数、写入行数、失败/跳过原因。
- 父任务派发子特工后未真正等待结果，又亲自重复执行搜索、提取、写表或发信链路。

## Verification（验收标准）

- 扫描结果只包含真实 `mp.weixin.qq.com` 原文链接、标题和发布时间。
- 每个新增品牌都有来源文章链接；正文未提及字段为空，不用模型常识补齐。
- 类目仅允许使用 Global Tree 20260427 标准表中的 `lvl1_cate_name`；无法对齐则留空并写明原因。
- 写入前完成表头读取、既有品牌读取、去重；写入后完成 RAW 回捞校验。
- 输出运行摘要：扫描篇数、新增品牌数、写入行数、失败/跳过原因。

## 触发场景

当用户要求“扫描欧洲跨境公众号并更新品牌库”“每周品牌库周扫”“eu-brand-library-weekly-scanner”时，使用本技能。

## 核心 SOP

### 执行编排模式（v1.4 新增）

- 若主进程选择派发子特工执行完整周扫，父任务只能做三件事：准备输入、派发任务、`wait_async_task` 等待结果。
- 在等待结果返回前，父任务不得再次执行搜索、网页抓取、品牌提取、飞书读写、候选源整理或消息发送，禁止与子特工重复跑业务链路。
- 一个运行窗口内只能有一个“业务执行器”：要么父任务亲自执行完整周扫，要么子特工完整执行，二选一，不得双跑。
- 子特工返回后，父任务只允许做结果汇总、最终摘要和必要的状态收口；若子特工已完成写表与 RAW 校验，父任务不得重复写表。

### 0. 数据源自动发现（方案B：人工确认扩源）

#### 0.1 每周候选源搜索

使用搜索能力（info-miner/网络搜索）以「欧洲跨境」「欧洲出海」「跨境品牌」「EU ecommerce 出海」等关键词，发现新的微信公众号/内容账号。每次产出 Top 5 候选源。

#### 0.2 自动质量评分（Quality Gate）

按 `memory/topics/eu-brand-scanner-datasource-judgment.md` 中的准入标准对候选源进行评估：

- ✅ 准入：地域聚焦欧洲市场 + 跨境电商垂直 + 有品牌颗粒度信息 + 内容质量高 + 近90天活跃
- ❌ 排除：国内市场内容 / 纯服务商广告 / 泛财经 / 僵尸号 / 付费墙
- 分级：通过 / 待确认 / 排除

#### 0.3 已收录数据源维护与去重

读取 `memory/topics/eu-brand-scanner-datasource-judgment.md` 中的「已收录数据源清单（SSOT）」，对候选源去重，避免重复推荐已在库的源。

#### 0.4 输出候选卡片（仅返回给主进程，不自动入库）

将「待确认」级别的候选源整理成结构化列表（名称、类型、理由、链接），通过 result 返回给主进程，由主进程发给用户确认。

用户确认后，才允许把新源追加写入 `memory/topics/eu-brand-scanner-datasource-judgment.md` 的「已收录数据源清单」和「历史候选记录」。本技能不得在未确认时擅自扩源。

### 1. 扫描公众号合集（范围扩展为多源）

扫描范围扩展为：`memory/topics/eu-brand-scanner-datasource-judgment.md` 的「已收录数据源清单」中所有状态为「活跃」的数据源。

对每个活跃数据源，按原有逻辑进入其公众号合集/文章列表页，分页抓取文章列表。默认只保留本周新增文章；若用户给出 `N`，改为最新 `N` 篇。每篇文章必须记录真实原文链接、标题和发布时间。若常规网页抓取遇到微信 Visitor System、登录墙或 403，先说明该批文章扫描失败原因，不得用搜索结果或转载链接冒充原文链接。

### 2. 提取品牌信息

对每篇新文章使用 `user_skills/info-miner` 做正文溯源与结构化提取。输出字段包括品牌名中文、品牌名英文、所属一级类目、目标市场/销售渠道、简介摘要、来源文章链接、来源文章标题、发布时间。正文没有明确提到的字段保持空值；不得根据品牌常识、标题猜测或外部资料补写。

### 3. 对齐类目标准

读取 Global Tree 20260427 标准表中的 `lvl1_cate_name`。将文章中出现的类目映射到标准一级类目；无法确定唯一映射时保持空值，并在跳过/备注原因中说明“类目无法零信任对齐”。

### 4. 去重与增量判定

读取「跨境品牌库」目标表格的表头和既有数据。以表头定位品牌中文列与品牌英文列；如果实际表头与 A 列+B 列约定不一致，以表头语义为准并在摘要中说明。将本次品牌中文名和英文名标准化后，与既有品牌名集合比较；中英文任一命中即视为已存在，跳过写入。

### 5. 写入飞书表格

使用 `user_skills/feishu-doc-writing-guide` 包装器执行写入。写入前必须按表头确认列位，不依赖固定列字母。将真正新增品牌逐行倒序插入第 2 行；禁止全表覆盖、禁止删除旧数据、禁止裸调原生 lark 写入工具。写入后执行 RAW 回捞，逐行核对品牌名、来源链接和关键字段。

### 6. 输出运行摘要

执行完毕后输出简洁摘要，至少包含扫描源数量、扫描篇数、新增品牌数、写入行数、失败/跳过原因。若没有新增品牌，也要说明扫描范围与去重依据。

## 运行前自检

执行前可运行本技能自带校验脚本，确认输入和关键 URL 合规：

```bash
python3 scripts/validate_run_contract.py --target-sheet-url "https://bytedance.my.larkoffice.com/sheets/S91BsutWshyGK9tcAapmoeYkyQb" --category-sheet-url "https://bytedance.larkoffice.com/sheets/shtcnYzaobnxlPVGox8hmSZ8b8d" --seed-url "https://mp.weixin.qq.com/s/aSQ1xUhYdtgv6U8UNJfjXQ"
```

脚本只做运行契约断言，不替代实际扫描、提取、写入和 RAW 校验。
