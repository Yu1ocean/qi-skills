# info-miner（信息挖掘）

将碎片化线索“顺藤摸瓜”追到最权威、最长文、最原始的出处，并按**原文语言**选择输出路径：

- **中文信息源**：直接抽取并结构化输出中文（不做英中双语翻译；不做左右双栏对照排版）。
- **非中文信息源**：输出英中双语逐段对照（左英文右中文），用于高保真对照阅读。

**当前版本：0.1.2（2026-05-04）**

## 适用场景（Trigger）
- 只有一个关键词、概念名、微博/推文短句，但想找到它真正指向的**原始长文/官方文章**
- 看到二手转述，想“溯源”到**原始出处**核对细节
- 找到原文后，希望快速获得：**关键信息总结 +（按原文语言）正文结构化或英中双语对照全文**

## 输入要求
- 一段碎片线索（文本即可）：可以是微博/推文片段、短贴内容、作者名+关键词、概念名、截图中的文字抄录等
- 可选：
  - 倾向的来源类型（官方博客 / 论文 / 产品公告 / 新闻 / 论坛长文）

## ⚙️ 核心架构 / SOP / 约束条件

### Step 0：语言判断分支（硬约束，必须执行）
- **默认输出语言 = 中文**（要点总结、结构化整理均以中文输出）。
- 当抓取到的原文**主要为中文**时（例如：中文字符占比明显、或站点明确为中文媒体/中文博客）：执行“中文源路径”。
- 当抓取到的原文为**非中文**时：执行“非中文源路径”。
- **严禁**中文源仍然输出英中双语翻译。
- **严禁**中文源使用左右双栏对照排版（包括 HTML `<table>` 两列表格、左右双列对照等任何形式）。

### Step 1：基于线索做“溯源式搜索”
- 使用 `search` 进行多轮搜索：从关键词 → 可能的作者/组织 → 可能的原始文章标题 → 原文站点
- 优先策略：
  - 优先官方域名 / 作者主页 / 论文官网 / 产品公告
  - 避免只停留在“转载/二手解读”，必须尽量追到首发来源

### Step 2：判定是否“唯一高度匹配”
- 若找到**高度匹配且唯一**的目标文章：直接进入 Step 3（一波流）
- 若存在多个疑似出处：
  1. 输出候选列表（建议 3~8 条），每条包含：
     - 标题
     - 作者/机构
     - 发布时间（若可得）
     - 站点/域名
     - 直达 URL
     - 为什么它可能是原始出处（简短理由）
  2. 向用户发起确认：请用户选择某一条作为目标（或允许用户给出新的线索）

### Step 3：抓取全文（必须使用网页提取工具）
- 使用 `browser_goto_and_extraction` 打开用户确认/你判定的目标 URL，提取正文全文并保存为本地 Markdown
- 若页面有分页、脚注、代码块、引用等，尽量完整提取

### Step 4：深度提炼（中文要点总结）
- **🛡️ 内容隔离法则（最高优先级）**：在进行要点提炼与翻译时，必须保持 100% 的客观中立，**仅限于对原文内容的归纳，严禁结合用户的电商工作背景（USER.md）进行任何商业转化、话术包装或过度引申。**
- 基于全文，提炼 3~6 个核心框架/观点（偏“框架化”，不是流水账摘要）
- 对每个框架/观点：给出 1~3 句中文解释，必要时补充关键术语释义

### Step 5：正文组织（按语言分支）

#### 分支 A：中文源 → 中文结构化直出
- **只输出中文**：对原文进行结构化整理与必要的术语补充；不翻译、不对照。
- 推荐输出结构：
  - 【模块一】💡 关键信息总结（中文）：3~6 个核心框架或观点
  - 【模块二】🧾 原文结构化阅读（中文）：
    1. 模块开头必须给出原文直达 URL（格式固定：`原文链接：https://...`）
    2. 正文按自然段落/小标题/列表组织（保留代码块、引用、脚注信息），必要时在段落后补充 1 句“结构化注解”
    3. **不使用**左右双列排版；**不生成**英中双语翻译

#### 分支 B：非中文源 → 英中双语左右对照（旧路径，仅外文源启用）
- 将原文按自然段落切分（以段落为最小对齐单元；不要按句子逐句切，避免破坏阅读节奏）
- 对每一段：生成高保真中文翻译
  - 保留技术原味和行业黑话
  - 专有名词、产品名、术语：第一次出现可在中文中括注英文（如有必要）
  - 不要过度意译，不要“写成科普文”，要尽量贴近原文

### Step 6：生成标准化飞书文档（必须遵守排版契约）

#### 输出结构（严格遵守）
- 【模块一】💡 关键信息总结（中文）：3~6 个核心框架或观点
- 【模块二】根据 Step 0 的语言分支选择：
  - **中文源**：🧾 原文结构化阅读（中文，普通段落排版；严禁双栏）
  - **非中文源**：🌐 深度双语对照阅读（左英文、右中文，逐段对齐）

#### 版式实现（仅限“非中文源”使用两列表格）
为保证写入稳定性，**仅当原文为非中文**时，使用 **HTML `<table>` 两列表格**（禁止 Markdown 管道表格 `|`）。

文档正文中的表格模板如下（示例，仅限非中文源）：

```markdown
## 【模块一】💡 关键信息总结
- **观点 1：……**
- **观点 2：……**
- **观点 3：……**

## 【模块二】🌐 深度双语对照阅读
原文链接：https://example.com

<table header-row="true" header-col="false" col-widths="480,480">
  <tr>
    <td>English</td>
    <td>中文</td>
  </tr>
  <tr>
    <td>
      第一段英文……

      （保持原段落）
    </td>
    <td>
      第一段中文翻译……

      （对应同一段落）
    </td>
  </tr>
</table>
```

#### 写入飞书的硬性要求（必须执行）
- 必须使用 `user_skills/feishu-doc-writing-guide` 的规范链路写入飞书文档：
  1. 先在本地生成 `.lark.md`（只写正文，不要写 H1 标题）
  2. 调用飞书文档创建工具将 `.lark.md` 转为 docx
  3. 创建完成后，必须执行赋权脚本，确保 `yuqinan@bytedance.com` 拥有 `full_access`

**⚠️ 鉴权要求：** 涉及飞书 API 调用时，必须通过 `bash` 工具直接执行，并设置 `include_secrets=true`。

## 失败重试策略
- 搜索结果不稳定：扩大/收敛关键词，加入作者/机构/站点限定
- 目标文章无法抓取：尝试替代 URL（如 canonical 链接、AMP、镜像页），或更换提取策略后重试
- 多候选无法判定：回到用户确认分支，避免“拍脑袋”选错出处
