# Upward Reporting Escalator

## Common Rationalizations（常见借口）

以下说法一旦出现，视为开始偏离技能目标，必须立刻切回本 SOP：

- “先把动作写全，领导自然会看懂重点。”
- “改成老板视角，开头加一句结论就够了。”
- “数字已经有了，不用再解释时间窗和目标意义。”
- “第三版只是在第二版上润色，不需要绑定资源和目标。”
- “先写个像样版本，责任和诉求可以会后再补。”
- “这只是普通汇报，不需要对照 L5 判断力要求。”
- “只要写出结果和动作，就自然能体现领域专家能力。”

## Red Flags（危险信号）

出现任意一条，必须纠偏后再继续输出：

- 结果仍按时间顺序复述动作，而不是先给业务判断。
- 只把原文压缩得更短，没有发生“判断层级”的跃迁。
- 写了很多动作，但看不出谁负责、卡点在哪、下一步先干什么。
- 数字仍是裸数字，没有挂到时间窗、目标或业务贡献。
- 第三版没有出现“资源、动作、目标、验证点”中的至少三项。
- 把“更像汇报”误当成“可供决策”，却没有给出明确支持请求或验证问题。
- 汇报只体现项目 owner 或执行推进，没有体现区域/类目 owner 的战略判断、结构性解法和生态协同。
- L5 gap 分析只泛泛评价“还需提升”，没有指出缺失的判断力维度和可直接改写的句子。

## Verification（强制验收清单）

当输出完成时，必须同时满足：

1. **阶段识别正确**：明确当前是在产出执行稿诊断、判断稿、决策稿，还是三阶全量输出。
2. **差异解释完整**：必须说明每一轮升级究竟升级了什么，而不只是给改写结果。
3. **判断前置成立**：第二版及以上，开头必须先回答“现在怎么看”。
4. **责任绑定成立**：第二版及以上，必须让读者看出关键责任链。
5. **锚点完整**：第三版必须至少补齐时间窗、目标锚点、业务意义三项中的两项以上。
6. **方案化完成**：第三版必须把判断、动作、资源或支持诉求收束成可讨论方案。
7. **输入不足显式提示**：若缺少目标、时间窗、资源前提等关键上下文，必须标注“待确认”，不得假装完整。
8. **L5 对标成立**：涉及绩效、自评、owner 型汇报或用户要求对齐职级时，必须输出“L5 gap 分析”，对照 L5 Seller-focused Roles 的判断力要求指出当前稿件差距。
9. **改写建议具体**：L5 gap 分析必须给出可直接替换的改写建议，至少覆盖 2 个缺口维度；若材料不足，必须写明“证据待补”，不得替用户编造。

## 📌 技能简介

这个技能不是普通润色器，而是**向上汇报升维器**：把一段执行型材料，沿着“执行事实 → 管理判断 → 决策方案”三层台阶往上推。它关注的不是句子更漂亮，而是**信息是否已经从‘我做了什么’升级成‘管理层可以怎么判断、怎么投资源’**。

默认输出语言为简体中文，语气要求结论先行、判断明确、动作收束、可直接用于管理层讨论。

## 适用场景

### 场景 1：从原始执行稿做三阶升级

**输入：**
- 1 段原始汇报文字；可选补充目标、时间窗、责任分工、关键数字。

**输出：**
- 原稿诊断
- 第二版判断稿
- 第三版决策稿
- 升级规律总结

### 场景 2：已有两版稿，继续补到决策稿

**输入：**
- 已有判断稿或两版对照稿
- 可选补充业务目标、资源诉求、关键验证点

**输出：**
- 当前版本缺口诊断
- 决策稿完整版
- 需要补齐的资源/数字/诉求清单

### 场景 3：复盘多轮改写，提炼可复用升级规律

**输入：**
- 2-3 版同主题汇报文本

**输出：**
- 每轮语言动作变化
- 每轮思维跳跃点
- 可沉淀的升级规则 / SOP

## L5 Seller-focused Roles 对标层

当用户的汇报对象涉及绩效自评、职级校准、owner 型职责、招商/商家增长、区域/类目负责人，或用户明确要求“对齐 L5 / L5 判断力 / seller-focused roles”时，必须在三阶升级之外额外启动 L5 对标层。该层的目标不是把稿件写得更高级，而是判断它是否已经体现 L5 所要求的**领域专家判断力**。

### L5 核心定位

L5 Seller-focused Roles 的胜任状态是：具备类目/领域发展策略的领域专家，通常负责新兴或小市场的类目，或成熟大市场中的细分类目；能针对精专领域、战略级大客户或重点突破类目制定全局发展策略，并通过创新商家模式实现业务规模化。

### L5 判断力维度

1. **角色定位**：是否从“更熟练的执行者”升级为“领域专家”，能定义增长问题、供给结构和平台招商策略。
2. **业务范围**：是否站在区域/类目 owner 视角，而不是单个项目 owner 视角；是否能拆目标、搭团队、培养协同能力。
3. **策略与判断**：是否基于电商格局、平台优先级、外部市场动态做关键判断，并影响整体业务方向。
4. **结构性解法**：是否解决体系性问题，沉淀招商标准、商家分层、跨团队机制、市场打法和可复制 Playbook。
5. **生态协同**：是否联动品牌、服务商、产品、市场、招商、运营、区域等上下游伙伴，形成多方共赢的合作生态。
6. **外部影响力**：是否能在品牌 C-level、行业组织、政府对口方或关键商家处建立影响力，并稳定外部生态。
7. **卖家策略**：是否基于 cohort / 分层 / 分群制定卖家策略，识别供给缺口、配置资源并验证结果。

### L5 gap 分析输出要求

L5 gap 分析必须回答三件事：第一，当前稿件已经体现了哪些 L5 判断力；第二，距离 L5 要求还缺哪些关键证据或表达；第三，应该如何把原句改成“领域专家 / 区域类目 owner / 结构性解法”的表达。缺口判断必须具体到维度，不能只写“战略性不足”。

推荐结构为：

```text
L5 gap 分析：
- 当前判断力层级：执行型 / 判断型 / L5 owner 型（择一，并说明原因）
- 已体现的 L5 维度：列 1-3 项，绑定原文证据
- 主要 gap：按角色定位 / 策略判断 / 结构性解法 / 生态协同 / 卖家策略等维度指出缺口
- 具体改写建议：给出可直接替换的句子或段落
- 证据待补：列出还需要补的数字、案例、协同方、资源诉求或验证点
```

## 核心升级规律

### Rule-E1｜先换回答的问题，再换句子

向上汇报的核心不是“把句子写短”，而是把回答的问题从“我们做了什么”换成“现在怎么看、为什么重要”。如果回答的问题没变，再多润色也只是执行稿。

### Rule-E2｜第二版必须补出责任链

从执行稿升级到判断稿，不只要有结论，还要让管理层看见责任如何落位：谁负责哪一段、哪条链路是关键、哪里还缺覆盖。

### Rule-E3｜第三版必须把目标和资源绑上去

决策稿的标志不是更正式，而是把判断、动作、目标、时间窗、支持诉求绑成一条链。管理层看到后能直接讨论“要不要投、投多少、先投哪”。

### Rule-E4｜数字不是证明勤奋，而是证明值得决策

同一组数字，在执行稿里只是进度；挂上时间窗、目标贡献、验证问题后，才是决策锚点。

### Rule-E5｜动作要收束成 2-3 层，而不是平铺成流水账

好的向上汇报不是把动作列齐，而是把动作收束成“主判断下的关键抓手”。层次越清楚，越能减少管理层自己拼图的成本。

## 三阶升级框架

### 第 0 阶：执行稿（输入态）
- 典型问题：动作多、判断少；数字散、锚点弱；角色与优先级不清。
- 处理目标：先识别核心卡点，不急着整体润色。

### 第 1 阶：判断稿（Version 2）
- 必答问题：**现在怎么看？最关键的变化/卡点是什么？**
- 语言动作：删平铺动作、抽两三条判断、把问题本质前置。
- 结构公式：**核心判断 × 1-2 条 + 动作收束 × 2-3 层**。

### 第 2 阶：决策稿（Version 3）
- 必答问题：**基于这个判断，资源、动作和目标怎么绑在一起推进？**
- 语言动作：补责任链、补目标锚点、补时间窗、补支持诉求或验证点。
- 结构公式：**判断 + 责任分工 + 三层抓手 + 目标/贡献 + 待决策事项**。

详细对照见 [three-stage-escalation.md](references/three-stage-escalation.md)。

## 输出协议

### 场景 1 输出格式

1. **原稿诊断**：一句话判断当前更像什么稿。
2. **升级方向**：本轮最该先补的 2-4 个动作。
3. **第二版｜判断稿**：输出可直接复制的完整版本。
4. **第三版｜决策稿**：输出可直接复制的完整版本。
5. **L5 gap 分析**：当触发 L5 对标层时，输出当前稿件的 L5 判断力差距和具体改写建议。
6. **规律总结**：说明这次升级对应了哪几条三阶规律。

### 场景 2 输出格式

1. **当前版本处于哪一阶**
2. **距离决策稿还缺什么**
3. **补齐建议**：按“责任 / 数字 / 目标 / 诉求 / 验证点”列缺口
4. **决策稿完整版**

### 场景 3 输出格式

1. **三轮演进总览**：从什么升级到了什么
2. **每轮语言动作**：删掉了什么、前置了什么、绑定了什么
3. **每轮思维跳跃点**：回答的问题如何变化
4. **可复用 SOP**：沉淀成 3-5 步方法
5. **可迁移边界**：哪些场景适用，哪些场景不必硬套

## 工作流 / SOP

### Step 1. 校验输入是否支持当前升级目标

优先运行：

```bash
python3 scripts/validate_escalation_input.py --json '{"source_text":"...","target_stage":3}'
```

- 若目标是第三版决策稿，但没有目标、时间窗、资源/支持信息，必须先标记缺口。
- 若只有原始执行稿，默认按“先出第二版，再出第三版”的路径处理。

### Step 2. 判断当前稿件所处台阶

先识别文本更像：
- **执行稿**：报动作、报进度、报状态
- **判断稿**：已经开始回答“现在怎么看”
- **决策稿**：已经能支撑管理层讨论资源与目标

### Step 3. 先做“问题升级”，再做“文字升级” 

改写时先完成三件事：
1. 抽出 1-2 条核心判断；
2. 收束责任链与动作结构；
3. 把关键数字挂到时间窗、目标贡献和验证问题上。

### Step 4. 按目标台阶产出版本

- **目标到第二版**：只要求“判断先行 + 结构收束 + 责任可见”。
- **目标到第三版**：必须追加“资源动作目标绑定 + 验证点 / 支持诉求”。

### Step 5. 启动 L5 对标层（按需强制）

若输入涉及绩效、自评、职级校准、seller-focused roles、招商/商家增长、区域/类目 owner，或用户明确要求对齐 L5，必须额外执行：
1. 判断当前稿件的判断力层级：执行型 / 判断型 / L5 owner 型。
2. 对照 L5 七个维度，识别已体现维度与缺口维度。
3. 给出“原表达 → L5 化改写方向 → 可复制改写句”的具体建议。
4. 对缺失证据显式标注“证据待补”，不编造数据或案例。

### Step 6. 用规律解释改写，不只给答案

最终输出时，必须指出：
- 从哪一阶升到了哪一阶；
- 这次完成了哪些关键跃迁；
- 还缺哪些信息才能进一步升级。

## 合规默认值（Defaults）

- 默认语言：简体中文
- 默认受众：管理层 / 项目负责人
- 默认输出：若用户未指定，只产出第二版判断稿 + 第三版决策稿
- 默认目标台阶：`target_stage=3`
- 默认缺口处理：关键信息不足时显式标注“待确认”
- 默认结构：判断在前，动作在后，诉求与验证点收尾
- 默认 L5 对标：绩效、自评、职级、seller-focused roles、招商/商家增长、区域/类目 owner 场景自动开启；其他普通汇报默认不开启，除非用户显式要求

## 脚本与运行时断言

使用 `scripts/validate_escalation_input.py` 做前置校验，确保：
- `source_text` 非空且达到最小长度
- `target_stage` 只能是 1/2/3
- 若目标是第三版，则至少显式给出 `goal_anchor`、`time_window`、`resource_binding` 三类信息中的一类；否则返回待补字段
- 若输入为多轮对比，版本数量和字段结构合法
- 当 `enable_l5_benchmark=true` 或输入命中绩效/自评/职级/seller-focused roles/招商/商家增长/区域/类目 owner 关键词时，校验结果必须返回 `l5_benchmark.enabled=true` 与对应触发原因
- L5 对标层不能要求用户一次性补齐所有证据；只要稿件存在，就先输出 gap 分析，并把缺失项列为“证据待补”

若校验失败，必须停止“假装完整输出”，转为“缺口诊断 + 待补信息清单”。

## ⚙️ 核心架构 / SOP / 约束条件

- 这个技能解决的是“汇报层级”问题，不是一般润色问题。
- 第二版的成功标准是“让管理层少拼一次图”；第三版的成功标准是“让管理层少追问一轮资源配置”。
- 不强行把所有汇报都写成宏大叙事；如果场景只是轻量同步，可以止步于第二版。
- 如果没有足够数据，不要编造目标或贡献值；用“待确认”保留决策位。
- 第三版不是把内容写长，而是把判断链闭合。

## 📖 案例实录 (Best Practice)

- 🧑‍💻 用户输入：
  ```text
  这周我们推进了多个商家沟通，也同步在梳理 EU 市场案例和合规资料，后续会继续跟进重点客户并完善打法。
  ```
- 🤖 标准输出：
  ```text
  原稿诊断：这段话仍是执行稿，信息说明了“做了什么”，但还没有回答“现在怎么看”。

  第二版｜判断稿：
  当前判断是，商家推进的核心问题已经不是触达动作是否发生，而是 EU 机会认知和决策资料是否足够支撑重点客户下判断。因此本周动作应收束为两条：一是持续跟进重点商家，验证高潜客户的真实转化意愿；二是加快补齐 EU 市场案例与合规资料，降低客户决策门槛。

  第三版｜决策稿：
  当前判断是，重点商家的推进瓶颈正在从“是否触达”转向“是否具备足够的 EU 市场信心与决策资料”。基于这一点，下一阶段动作不再平铺推进，而是绑定两条主线：第一，由业务同学聚焦高潜客户跟进，优先验证本月重点客户的真实转化概率；第二，由策略与支持侧补齐 EU 市场案例和合规资料，在本月内形成可复用的商家决策包。若这两条链路跑通，后续重点不是继续扩大动作面，而是判断现有资料与客户池是否足以支撑下阶段招商目标；若不足，则需要追加资源支持。
  ```
