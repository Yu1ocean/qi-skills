# 全域信息洞察分析器（Internet Insight Analyzer）

将“用户给定的课题/事件”转化为一份可落地的互联网洞察研报：先做信息广度覆盖，再做关键来源深挖，最后做降噪清洗、交叉验证与矛盾点拆解，并以 **L1-L4 分层框架 + 行动导向建议** 的形式输出。

## 何时使用

在需要基于公开互联网信息快速建立认知并给出建议时使用，例如：
- 行业/公司/产品的阶段性研究（趋势、格局、机会、风险）
- 突发事件/争议事件的信息核查与影响评估
- 政策/监管/宏观变化对业务的传导分析
- 竞品情报与对标拆解（产品、定价、渠道、叙事）
- 舆情扫描：观点分布、关键叙事、争议与反驳

## 需要的输入（用自然语言即可）

尽量从用户输入中抽取/补齐以下要素（缺失则在不打断主流程的前提下做最小澄清）：
- **研究对象**：一个宏观课题或具体事件
- **时间窗口**：例如“最近 7 天/30 天/2024Q4/某日期区间”（若未给出，默认近 90 天，并在报告中明示）
- **关注维度**：如“商业影响/技术路线/政策风险/投资判断/公共舆论”等
- **输出偏好**：篇幅（短报/中报/长报）、语言、是否需要表格

## 核心工作流（强制执行的 SOP）

### 1) 定义研究问题与边界（2-5 句）
- 将用户输入改写为 1-3 条可检索的问题（可含假设）。
- 明确“本报告不做”的范围（例如：不做内幕信息、不做付费数据库、不做法律意见）。

### 2) 广度提取：多路检索（Breadth）
- 使用 `search` 工具对同一主题做 **多角度、多语言、多来源类型** 的查询组合：
  - 事实类：时间线、公告、数据、监管/政策文本
  - 观点类：专家/媒体/社区讨论
  - 供给侧/需求侧：公司、渠道、用户、竞品
- 若用户问题包含 **网站流量/访问量/排名/流量来源/竞品/国家分布** 等互联网统计指标：
  - 必须使用 `search` 并设置 `source="similar_web"` 获取数据；
  - 该数据视为唯一权威数据源，不与其他零散来源做“拼接/平均”。
- 形成“候选来源池”（建议 20-60 条链接），并对每条记录：标题、URL、来源类型、发布日期（若可得）、一句话要点。

### 3) 深度抓取：关键来源精读（Depth）
- 对“高信息密度/高权威/高争议”的来源，使用 `browser_goto_and_extraction` 抽取原文要点。
- 对需要交互才能获取内容（登录/分页/动态加载）的页面，再使用 `browser_use`。
- 若目标链接为 **微信文章（weixin）/知乎/ByteTech** 等：优先（或必须）使用 `browser_goto_and_extraction`，不要使用 `browser_use`。
- 严禁使用 `browser_use` 访问飞书文档/表格/多维表格链接（例如 `bytedance.larkoffice.com/docx|docs|sheets|base|wiki`）。
- 输出“证据片段”（Evidence Snippets）：
  - 关键原句/数据 + 链接 + 发布时间/更新时间 + 该片段支撑的结论点。

### 4) 降噪清洗与交叉验证（Denoise & Cross-check）
- 去重：相同新闻稿/转载稿视为同一来源链。
- 分层：区分 **一手事实**（公告、论文、法规、财报）与 **二手解读**（媒体/自媒体）与 **三手转述**。
- 交叉验证：
  - **关键结论** 至少有 2 个相互独立来源支撑；
  - 若仅有单一来源，必须标注“待验证”，并给出需要补证的方向。
- 争议点拆解：列出“支持证据 vs 反证/空白证据”。
- 来源可信度评分：必要时读取 `references/source-scoring.md` 使用统一口径。

### 5) 结构化分析：L1-L4 分层框架（必须使用）

- **L1｜事实层（What happened / What is true）**
  - 时间线、可核查数据、明确发生的动作
  - 只写可证据化的内容；不写推测

- **L2｜解释层（Why / So what）**
  - 利益相关方与动机（公司/监管/用户/竞品/资本/媒体）
  - 约束条件与结构性原因（供需、成本、技术、政策、组织）

- **L3｜分歧层（Where disagree / What uncertain）**
  - 主要争议与对立叙事
  - 不确定变量与信息缺口
  - 场景推演：至少给出 2-3 个情景（基准/乐观/悲观）与触发信号

- **L4｜行动层（What to do next）**
  - 面向行动的结论：可执行、可衡量、可复盘
  - 分时间尺度：48 小时 / 2 周 / 1-3 个月（按任务类型调整）
  - 给出“监控指标/预警信号/下一步信息补采清单”

### 6) 研报输出（固定结构 + 行动导向）

始终按以下结构输出（允许在不破坏层级的前提下增删小节）：

1. **标题**（包含研究对象 + 时间窗口）
2. **执行摘要（TL;DR）**：3-7 条要点（结论优先）
3. **研究问题与范围**
4. **信息面概览**：本次使用的来源类型分布、时间分布、覆盖面边界
5. **L1-L4 正文**（四层必须齐全）
6. **行动建议清单**：按优先级/负责人/时限（若用户未指定负责人则留空）
7. **风险与反例**：至少 3 条（信息偏差、样本偏差、时间滞后、幸存者偏差等）
8. **参考链接（必选）**：按“高→中→低可信度”排序

## 输出质量约束（必须遵守）

- **来源可追溯**：任何重要结论都必须附上链接（至少在“参考链接”中出现）。
- **事实与观点分离**：L1 不写推测；L2-L4 的推论必须写清证据链强弱。
- **不确定性显式化**：无法验证的点用“待验证/信息缺口/单一来源”标注。
- **时间敏感性声明**：报告开头或信息面概览中写明“检索截至时间”。
- **不做伪精确**：没有数据就不要编造数值；用区间/趋势/定性替代。

## 推荐的记录格式（用于内部推理，不一定要全部输出）

- 来源条目：`[标题] | [URL] | [发布时间] | [来源类型] | [一句话要点]`
- 证据片段：`[结论点] ← [原句/数据]（URL，时间）`
- 争议矩阵：`观点A(证据) vs 观点B(证据) vs 缺口(需要什么证据)`
