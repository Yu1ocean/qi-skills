## 📌 技能简介
将用户给定的“宏观课题/具体事件”转化为一份可落地的互联网洞察研报：先做信息广度覆盖，再做关键来源深挖，最后做降噪清洗、交叉验证与矛盾点拆解，并以 **L1-L4 分层框架 + 行动导向建议** 输出。

## 🔑 触发词
- 核心关键词：
  - 互联网洞察
  - 竞品情报 / 竞品研究
  - 舆情扫描 / 舆情核查
  - 政策解读 / 监管影响
  - SimilarWeb / 网站流量 / 访问量 / 排名
- 典型指令示例：
  > 帮我做一份“OpenAI Sora”最近 30 天的公开信息洞察，按 L1-L4 输出并给出行动建议。
  > 分析下「某公司被监管约谈」这件事，先核查事实链，再给出不同情景下的影响与下一步关注点。
  > 对比 a.com 和 b.com 的流量与来源结构（SimilarWeb），并解释差异可能来自哪里。

## ⚙️ 核心架构 / SOP / 约束条件
- **核心流程（强制）**：定义研究问题与范围 → 广度检索（Breadth）→ 关键来源深挖（Depth）→ 降噪与交叉验证（Denoise & Cross-check）→ **L1-L4 分层输出** → 行动建议与监控清单。
- **工具选择规则（关键）**：
  - 若用户问题包含 **网站流量/访问量/排名/流量来源/竞品/国家分布** 等互联网统计指标：必须使用 `search(source="similar_web")` 获取数据（视为唯一权威数据源）。
  - 对微信文章/知乎/ByteTech 文档：优先使用 `browser_goto_and_extraction` 抽取信息。
- **质量约束（硬性）**：
  - 重要结论必须可追溯（至少在参考链接中出现）。
  - 事实与观点分离：L1 不写推测；L2-L4 的推论要写清证据链强弱。
  - 不确定性显式化：单一来源必须标注“待验证”，并说明需要补证的材料类型。

## 📖 案例实录 (Best Practice)
- 🧑‍💻 用户输入：
  ```text
  我们准备做一个“AI 助手”产品，对标市场上 3 个头部产品。请你基于公开信息做一份竞品洞察（最近 90 天），重点关注：产品定位、商业化、渠道与用户口碑；输出按 L1-L4 分层，并给出 48 小时/2 周/1-3 个月的行动建议。
  ```
- 🤖 标准输出：
  ```text
  标题：AI 助手竞品洞察（近 90 天）

  TL;DR：
  - 结论 1（附关键证据链接）
  - 结论 2（附关键证据链接）
  - 结论 3（待验证：需要补证材料类型）

  L1｜事实层：
  - 产品 A：近期发布/功能迭代/定价动作（链接+时间）
  - 产品 B：渠道动作/增长数据（链接+时间）

  L2｜解释层：
  - 可能的商业化路径与约束条件（证据链强/弱标注）

  L3｜分歧层：
  - 争议叙事 A vs 叙事 B（各自证据与缺口）
  - 情景推演：基准/乐观/悲观 + 触发信号

  L4｜行动层：
  - 48 小时：补采信息清单 + 快速验证实验
  - 2 周：MVP 方案与对标差异点
  - 1-3 个月：产品路线/渠道策略/监控指标

  参考链接：
  - S/A 级来源优先，其次 B/C 级；按可信度从高到低排序
  ```
