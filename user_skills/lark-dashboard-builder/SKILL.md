# 飞书统计看板构建器（lark-dashboard-builder）

## Common Rationalizations（常见借口库）

以下话术一旦出现，视为准备绕过护栏，必须立刻停下并回到 SOP：

- “我大概知道这列是什么意思，不用读表头了。”
- “非空值很多，先拿 `<>""` 顶一下。”
- “先把公式写上去，口径回头再问。”
- “看板标签列已经写好了，公式直接引用左边单元格就行。”
- “回捞全是 0 也没事，可能晚点会刷新。”

## Red Flags（危险信号）

出现任意一条，必须熔断或先向用户确认：

- 未读取底表表头与样本 distinct 值，就直接开始写公式。
- 将状态类字段写成 `<>""`、`ISBLANK` 之类的非空口径替代精确值匹配。
- 口径三问没有完整确认，却准备执行写入。
- 公式引用了看板自身标签列，而不是把维度值硬编码进 COUNTIFS。
- 写入后没有做 RAW 回捞，或回捞结果全为 0 仍宣称成功。
- 漏斗结构没有校验“分支和 = 入口”，就直接交付。

## Verification（强制验收清单）

当宣称“看板已完成”时，必须同时满足：

1. **Step 0 侦察完成**：拿到列名映射表，以及各维度列/口径列的 distinct 精确值清单。
2. **Step 1 三问已确认**：分母、分组维度、每列统计口径都得到用户明确确认。
3. **P3 雷区已排查**：若某候选口径列非空占比 >80%，已明确提示风险，且未用 `<>""` 偷渡状态判断。
4. **公式已写入**：COUNTIFS 公式写入目标看板 Sheet 指定区域，且维度值硬编码在公式里。
5. **RAW 回捞通过**：写入后立即读回公式区/结果区，不能只汇报“已写”。
6. **结果非零**：至少一个核心统计列结果不全为 0；若全为 0，必须视为异常并排查。
7. **漏斗断言通过**：若看板是漏斗结构，分支列之和与入口列误差不得大于 1；否则必须报警。

## 📌 技能简介

这个技能用于把飞书表格底表，快速锻造成可维护的统计看板。它的职责不是替人拍脑袋定义业务口径，而是在用户明确“要什么”之后，负责把底表侦察、公式生成、写入与验证这条链路做扎实。

## ⚙️ 核心架构 / SOP / 约束条件

### P1 · 人机分工（置顶）

- **人类负责**：定义看板布局、业务语义、口径决策，也就是“要什么”。
- **Aime 负责**：侦察精确值、生成公式、写入验证、定时快照，也就是“怎么取”。
- 因为业务口径是业务决策，不是公式推理题，所以 Step 1 的三问必须由人类拍板，不能跳过。

### P2 · 口径三问

每次写列公式前，都必须拿到以下三项明确答案：

1. **分母是谁？** 是否限定某列=某值，还是全量统计？
2. **分组维度是什么？** 按哪一列、哪些精确值分行？
3. **每列统计口径是什么？** 每个统计列分别对应哪个字段的哪个精确值？

如果任一项缺失，只能停在侦察报告，不得下钻到写入。

### P3 · 非空口径是雷区

- 状态类字段必须优先使用 distinct 精确值匹配。
- 如果某候选列的非空值占比超过 80%，说明它更像“几乎人人都有内容”的记录列，不适合直接拿来做状态统计。
- 遇到这种情况，必须主动质疑并让用户重新确认字段语义；禁止直接用 `<>""` 代替状态判断。

### 何时使用

适用于以下任务：

- 用户已有飞书 Sheets 底表，希望快速做统计看板。
- 需要用 COUNTIFS 构造漏斗、阶段分布、状态分布、分组快照。
- 需要先摸清列语义与 distinct 精确值，再决定统计口径。
- 需要把公式安全写入已有看板 Sheet，并且写后验证。

不适用于：

- 用户只想做一次性 SQL/Pandas 分析，不需要飞书看板落地。
- 需要复杂透视表、图表样式、美化排版为主的任务。
- 底表字段定义本身混乱到无法确认业务语义，且用户暂时无法给出口径决策。

### 前置依赖

1. 读取或写入飞书表格前，先加载 `inner_skills/lark-sheets` 与 `inner_skills/lark-shared`，按其中的 MCP 约束执行。
2. 涉及已有飞书文档/表格的修改时，遵循 `user_skills/feishu-doc-writing-guide` 的 RAW 原子锁规范。
3. 若需要把本地辅助脚本结果再写回飞书，相关 `bash` 调用必须设置 `include_secrets=true`。

### 输入参数

- 工作簿 ID
- 底表 Sheet ID + 数据行范围
- 目标看板 Sheet ID
- 看板结构描述（可选；若缺失，先做 Step 0 侦察）

### 输出

- 写入完成后的看板截图或回捞数据
- 验证报告（含漏斗完整性断言结果）

## 工作流（四步流水线）

### Step 0（代码自动）：底表侦察

目标：先搞清“列字母对应什么语义、各列到底有哪些精确值”。

执行动作：

1. 读取底表表头行，输出“列字母 → 表头名称”的映射。
2. 读取候选维度列与口径列的数据值，统计 distinct 精确值、非空占比、样本量。
3. 产出侦察报告：
   - 列名映射表
   - 各口径列的 distinct 值清单
   - 非空占比警报（若 >80%）

如需用本地脚本汇总侦察结果，可运行：

```bash
python3 scripts/profile_sheet_snapshot.py --input /path/to/bottom_sheet.csv --header-row 1 --columns B,Q,V
```

脚本会输出 JSON，包含列名、distinct 值、非空率、疑似 P3 雷区提示。

### Step 1（人机交互）：口径三问

Step 0 完成后，必须把侦察结果发给用户，并逐项确认：

1. 分母是谁？
2. 分组维度是什么？
3. 每列统计口径是什么？

若用户给出的口径涉及状态列，但候选列的非空占比 >80%，必须主动提醒：

> 这列更像记录列而不是状态列，直接用 `<>""` 统计会有高误伤风险。请确认是否改用某个精确状态值。

未得到三问答案前，禁止开始公式写入。

### Step 2（代码自动）：公式生成与写入

根据 Step 1 已确认的口径：

1. 把底表范围、分母过滤、分组维度、指标定义整理为 formula spec。
2. 生成 COUNTIFS 公式；所有维度值都要硬编码，不引用看板标签列。
3. 使用 `lark_sheets` MCP 写入目标看板 Sheet 的指定范围。
4. 禁止裸调 OpenAPI。

本地公式生成可使用：

```bash
python3 scripts/generate_countifs_dashboard.py --spec /path/to/spec.json --output /path/to/formulas.json
```

`spec.json` 推荐结构：

```json
{
  "source_sheet": "底表!A1:Z9999",
  "group_dimension": {"column": "Q", "values": ["Alice", "Bob"]},
  "denominator_filters": [{"column": "B", "value": "必招 6 月"}],
  "metrics": [
    {"label": "入驻数", "filters": [{"column": "V", "value": "已入驻"}]},
    {"label": "拒绝数", "filters": [{"column": "V", "value": "未入驻"}]}
  ],
  "target": {"start_cell": "B3"}
}
```

### Step 3（代码自动）：验证

写入后立即验证：

1. 回捞公式区与结果区，确认写入成功。
2. 若结果全为 0，视为异常，不得草草交付。
3. 若包含漏斗结构，校验各分支列之和是否等于入口列，误差 >1 立刻报警。
4. 输出验证报告，包括：
   - 读回结果
   - 是否触发全零警报
   - 漏斗完整性断言结果

本地验证可使用：

```bash
python3 scripts/validate_dashboard_snapshot.py --input /path/to/readback.json --funnel-entry 0 --funnel-branches 1,2,3
```

## Defaults（合规默认值）

- 默认先做 Step 0 侦察，再进入口径确认。
- 默认把 distinct 值当作精确枚举值，不做模糊匹配。
- 默认禁用 `<>""` 状态口径；只有用户明确指定且风险已提示时，才允许保留。
- 默认在公式中硬编码维度值，避免看板标签修改导致公式漂移。
- 默认写后即读，并把回捞结果作为验收证据。

## 脚本工具箱

- [generate_countifs_dashboard.py](scripts/generate_countifs_dashboard.py)：把口径 spec 编译成 COUNTIFS 公式矩阵。
- [validate_dashboard_snapshot.py](scripts/validate_dashboard_snapshot.py)：对回捞结果做非零校验与漏斗完整性断言。

  用这个飞书底表，做一个按负责 BD 分组的漏斗看板：先侦察 distinct 值，再和我确认分母、分组、每列口径，最后把 COUNTIFS 公式写进看板 Sheet。

  ```text
  先执行 Step 0：读取底表表头与候选字段 distinct 值，产出列名映射表和精确值清单。

  用户确认后，执行 Step 2：生成维度值硬编码的 COUNTIFS 公式，并通过 lark_sheets MCP 写入看板。
  最后执行 Step 3：立即回捞验证；若全零或漏斗和不守恒，直接报警并停止伪交付。
  ```
