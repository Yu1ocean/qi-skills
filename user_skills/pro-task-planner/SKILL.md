# Pro Task Planner（高级任务拆解规划师）

将“先干再说”的冲动拦在门外：在开始任何复杂实现/分析之前，先把任务拆成可执行、可验证、可协作的计划。

## 何时必须使用

满足任一条件时，必须先输出“任务拆解计划”，然后再进入实际执行：

- 任务涉及**编码/重构/排障/性能优化/数据分析/报告生成**，且结果需要稳定可复现。
- 需要修改多个文件或多个模块，或需要在不同环境/系统间交互。
- 用户目标或约束存在不确定性（例如缺少输入样例、验收口径不清、交付形式未定）。
- 失败代价高（会影响线上、影响他人协作、或返工成本明显）。

若任务非常小（例如单函数、小段文案改写），也可以使用本 Skill 的“轻量模式”：只输出简化版计划 + 验证清单。

## 输出要求（必须遵循）

输出一个**可直接执行的计划**，包含以下固定结构（标题名可保持一致）：

1. **Goal（目标与交付物）**
   - 目标一句话描述
   - 交付物清单（文件/文档/链接/可运行产物）
   - 非目标（明确不做什么）

2. **Assumptions & Questions（假设与澄清问题）**
   - 先列出假设（明确标注“未确认”）
   - 再给出需要用户确认的问题（控制在 3~7 个，按优先级排序）

3. **Plan（任务拆解）**
   - 用表格列出每一步：
     - Step
     - 目的（Why）
     - 输入（Input）
     - 输出/产物（Output）
     - 依赖（Dependencies）
     - 风险点（Risks）
     - 验证标准（Verification / Exit Criteria）

4. **Milestones（里程碑与顺序）**
   - 说明关键里程碑（例如：环境准备完成、核心路径跑通、测试通过、交付完成）
   - 标注关键依赖链（哪些步骤必须先做，哪些可以并行）

5. **Verification（强制验证）**
   - 给出一个用户可直接核对的 checklist（见下方模板）

6. **Stop Point（停机点）**
   - 明确写出：**“在用户确认计划/回答关键问题之前，不进入实现或大规模改动。”**

## Common Rationalizations（AI 常见的偷懒借口）

以下借口一旦在脑中出现，必须立即停止，并回到“输出计划”这一步：

- “这个任务看起来很简单，不需要详细规划。”
- “我可以边写代码边思考，先把主干写出来再说。”
- “我已经理解了需求，不需要跟用户确认。”
- “先把结果做出来给用户看，细节之后再补。”
- “写计划太慢了，会拖延交付。”
- “用户没要求计划，我就直接做。”
- “先收集上下文/跑起来/试试看，再决定要不要规划。”

## Why they fail（为什么这些借口是错的）

- **边写边想**：容易把临时决策固化进结构，导致架构混乱、耦合升高，后续每一步都变成“带着错误前提继续堆”。
- **不确认需求**：需求理解偏差通常不会在第一步暴露，而是在快交付时炸锅，返工成本最高。
- **先做结果再补计划**：这是“后验合理化”，计划会变成对已发生行为的解释，而不是约束；质量门禁失效。
- **觉得计划拖慢速度**：短期看似更快，长期必然在回滚、修修补补、解释成本上付利息。
- **用户没要求**：复杂任务的风险由执行者承担；计划是风险控制，不是可选装饰。
- **先收集上下文再说**：没有目标与验证口径的上下文收集会变成无穷无尽的浏览与猜测。

## Red Flags（危险信号）

出现任一信号时，必须停下补齐计划或回退：

- 在没有写出**验证标准**之前就开始改代码/跑分析。
- 步骤跨度过大（例如“一步完成架构重构并上线”）。
- 不知道下一步需要什么输入，或者输出是什么。
- 计划里没有明确的“产物”，只有抽象描述（例如“优化一下性能”）。
- 依赖关系不清：不知道哪些步骤是前置、哪些可并行。
- 没有风险预案（例如失败了怎么回滚、如何定位问题）。
- 发现自己在“解释为什么不用计划”，而不是在“产出计划”。

## Verification（强制验证：用户核对清单）

在进入执行前，必须输出并让用户核对以下 checklist（可复制粘贴给用户勾选）：

- [ ] 目标一句话描述准确，且与我需求一致
- [ ] 交付物清单明确（我知道最终会拿到什么）
- [ ] 非目标已列出（我知道哪些不在范围内）
- [ ] 关键假设已标注，且我已确认/修正
- [ ] 关键问题已回答（或已同意先按假设推进）
- [ ] 拆解步骤足够细（每步 30~90 分钟级别或可独立验证）
- [ ] 每步都有明确产物与退出条件（验证标准可执行）
- [ ] 依赖关系清楚（哪些必须先做、哪些可并行）
- [ ] 风险点已识别，且有回滚/失败处理策略
- [ ] 我同意在确认计划前，AI 不做大规模实现或不可逆改动
