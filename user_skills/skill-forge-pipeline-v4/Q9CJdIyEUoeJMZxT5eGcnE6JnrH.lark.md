## 📌 技能简介

**info-miner（信息挖掘）** 是一款面向「碎片化线索 → 权威原文 → 标准化阅读 → 闭环归档」的全链路溯源技能。它能够顺着一段微博、一条推文、一个概念名甚至一张截图里的关键词，一路追到最权威、最长文、最原始的出处，再按**原文语言**自动选择输出形态：

- **中文源**：直接抽取并结构化输出中文，不做翻译，不做双栏对照。
- **非中文源**：输出英中双语逐段对照（左英文、右中文），用于高保真阅读。

更关键的是，从 **v0.5** 起，info-miner 已把规则升级为两条硬红线：一是 **飞书文档与灵感卡片必须物理分离**，禁止再把卡片前置嵌入说明文档头部；二是交付链路新增 **payload 防污染护栏**，所有 card / post payload 必须走 `.ephemeral_pool` 唯一路径并在发送前做主题一致性断言。归档失败或断言失败均需立即熔断，彻底杜绝"文档建出来了但资产串味 / 误发 / 找不到"的黑洞。

## ⚙️ 核心架构 / SOP / 约束条件

info-miner 的执行链路由 **1 个硬熔断闸门 + 8 个标准步骤** 串联组成，并由两个物理护栏脚本兜底：`scripts/preflight_target_assertion.py`（Phase 0 断言层）与 `scripts/wiki_archive_guard.py`（归档 L2/L3 护栏）。

### 🚨 文档生动化标准（归档场景强制）

- **物理分离铁律**：调用 `cyber-inspiration-generator` 生成的灵感卡片、小说文案或视觉图，必须与理性的飞书文档完全分离；可以独立发送、独立归档，但**严禁**再嵌入文档头部概览区或正文模块。
- **payload 防污染**：凡需交付飞书卡片 / post / payload，必须先落盘到 `/workspace/.ephemeral_pool/`，并使用 `[TASK_ID]_[TOPIC_SLUG].card.json` / `[TASK_ID]_[TOPIC_SLUG].post.json` 之类的任务唯一文件名；严禁复用根目录 `card.json`、`post.json`、`payload.json` 等静态路径。
- **发送断言与上下文熔断**：正式发送前必须执行主题一致性断言，确认 payload 与当前任务意图、topic、task_id 一致；发送成功后必须清空本轮卡片 DSL / payload 摘要 / 临时话术，禁止把上一轮内容隐式复用到下一轮任务。

### 3.1A 新增交付护栏（v0.5）

- **交付解耦**：飞书文档链接与灵感卡片必须作为两条独立资产交付，禁止混装在同一张富文本消息卡片里。
- **归档前自查**：若调用 `cyber-inspiration-generator` 生成 EP-CARD，必须先确认其已独立入灵感台账，再继续 Wiki 归档。
- **失败即熔断**：只要出现路径不唯一、主题不一致、或发送后上下文未清理等情况，一律不得宣称交付成功。

### Phase 0：目标前置校验（硬熔断，必须最先执行）

> 第一动作不是搜索、不是全文抓取、不是排版，而是先确认拿到的就是用户想要的那篇文章。

**第一动作：轻量抓取（Lightweight Probing）**

拿到 URL 后，**只**提取以下元信息，严禁进入全文抓取 / 翻译 / 排版 / 飞书写入等副作用动作：

- 标题（`<title>` / `<h1>` / `og:title` 等）
- 作者 / 署名（若可得）
- 发布时间 / 更新时间（若可得）
- 域名 / 站点名
- 首段摘要：**200\~400 字**核心内容预览，不要全文

**第二动作：分支处理**

| 分支 | 触发条件 & 处理方式 | 判定 / 熔断规则 |
|-|-|-|
| **分支 A** | 用户提供了上下文（截图、关键词、作者名、主题描述等）。必须把轻量抓取得到的标题/作者/摘要/域名，与用户上下文做**三维交叉比对**：作者匹配度、主题匹配度、关键词覆盖度。 | 三个维度均明确匹配 → 通过 Phase 0；任一维度明显不一致或模棱两可 → **立即熔断**，输出「⚠️ 目标不一致告警」。 |
| **分支 B** | 用户未提供上下文。必须先输出【目标确认卡片】（标题 / 作者 / 发布时间 / 域名 / 首段摘要），等待用户显式确认。 | 未拿到「是 / 确认 / 继续」之前，禁止进入 Step 1+。 |

**Phase 0 物理护栏脚本（L3 断言层）**：

进入 Step 3+ 之前，必须调用 `scripts/preflight_target_assertion.py` 的 `assert_phase0_ready` 入口；任一维度不满足即 `raise PhasePreflightError`：

```Python
from preflight_target_assertion import assert_phase0_ready

assert_phase0_ready(
    probe={
        "title": "...",
        "author": "...",
        "publish_time": "...",
        "domain": "...",
        "summary": "≤400 字首段摘要……",
    },
    expected={"author": "...", "topic": "...", "keywords": ["..."]},
    # 或 user_reply="确认"
)

```

自检命令：

```Bash
python3 user_skills/info-miner/scripts/preflight_target_assertion.py --selftest

```

### Step 0：语言判断分支（硬约束）

- **默认输出语言 = 中文**（要点总结、结构化整理均以中文输出）
- 原文主要为中文 → 走"中文源路径"
- 原文为非中文 → 走"非中文源路径"
- **严禁**：中文源输出双语翻译，或中文源使用左右双栏排版

### Step 1 → Step 5：从溯源到正文组织

| Step | 动作 | 关键约束 |
|-|-|-|
| **Step 1** | 溯源式搜索 | 使用 `search` 多轮搜索：关键词 → 可能作者/组织 → 可能标题 → 原文站点。优先官方域名 / 作者主页 / 论文官网 / 产品公告，避免停留在转载或二手解读。 |
| **Step 2** | 判定唯一高度匹配 | 找到唯一高匹配 → 直接进入 Step 3；存在多候选 → 给出 3\~8 条候选清单（标题 / 作者 / 发布时间 / 站点 / URL / 简短理由），请求用户确认。 |
| **Step 3** | 抓取全文 | 用网页提取工具抓取已确认目标 URL 的正文全文，保存为本地 Markdown；分页、脚注、代码块、引用尽量完整。 |
| **Step 4** | 深度提炼（中文要点总结） | **🛡️ 内容隔离法则（最高优先级）**：只允许做客观归纳，**严禁**结合用户的电商工作背景做商业转化、话术包装或过度引申。提炼 3~~6 个核心框架/观点，每个 1~~3 句中文解释。 |
| **Step 5** | 正文组织（按语言分支） | **中文源**：只输出中文，结构 = 【模块一】💡 关键信息总结 + 【模块二】🧾 原文结构化阅读，模块二开头必须给出原文直达 URL。**非中文源**：以**自然段**为最小对齐单元生成英中双语对照，专有名词首次出现可在中文中括注英文。 |

### Step 6：生成标准化飞书文档（排版契约）

**输出结构（严格遵守）**：

- 【模块一】💡 关键信息总结（中文）：3\~6 个核心框架或观点
- 【模块二】根据语言分支选择：

  - **中文源** → 🧾 原文结构化阅读（中文，普通段落排版；**严禁**双栏）
  - **非中文源** → 🌐 深度双语对照阅读（左英文、右中文，逐段对齐）

### 🔁 失败重试策略

- **搜索结果不稳定**：扩大 / 收敛关键词，加入作者 / 机构 / 站点限定
- **目标文章无法抓取**：尝试 canonical 链接、AMP、镜像页，或更换提取策略重试
- **多候选无法判定**：回到用户确认分支，避免拍脑袋选错出处
- **归档分类不确定**：先用显式分类；没有显式分类时再推断；若仍无法落入白名单，则停止并说明分类无法确定
- **归档写入失败**：重新下载目标 Wiki 文档并核查 `## 📂 已归档资产` 区块；若仍失败，必须报错中断，不得只交付文档链接
