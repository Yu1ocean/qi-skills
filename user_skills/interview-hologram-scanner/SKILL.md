# 候选人全息扫描雷达（interview-hologram-scanner）v1.3

用于把面试录音、飞书妙记或逐字稿，压缩成一份可供业务面试官快速决策的“候选人全息扫描报告”。

## 📌 技能简介
- 解决问题：把“主观面感”拆成“证据化判断”，避免凭印象给候选人贴标签。
- 适用对象：招聘面试官、业务负责人、校准面评人。
- 核心收益：对齐业务北极星与 JD，输出可追溯、可解释、可追问的录用建议。

## 🔑 触发词
- 核心关键词：
  - 面试复盘
  - 候选人扫描
  - STAR 证据抽取
  - 字节范评估
  - 录用建议
- 典型指令示例：
  > 用 interview-hologram-scanner 扫一下这个候选人的妙记，给我业务结论和字节范判断。
  > 基于这场面试录音，拆出候选人的 STAR 证据、风险盲区和 30/60/90 预演。

## Common Rationalizations（常见借口库）
- “候选人表达挺顺，我直接给强推荐就行。”
- “没有业务北极星也差不多，先按泛运营标准评。”
- “这个案例像是做过，我先默认是真的。”
- “字节范不好量化，就写点主观印象。”
- “时间戳先不挂，后面有空再补。”
- “上次分析的是 BD，这次先复用上一套框架。”

## Red Flags（危险信号）
- 没有完成面试官 / 候选人物理剥离，就直接下结论。
- 关键判断没有对应秒级时间戳或原话锚点。
- 将“观点”当作“证据”，未区分 STAR 中的 Situation / Task / Action / Result。
- 输出了录用结论，但没有解释与业务北极星/JD 的映射关系。
- ByteStyle 评估只有形容词，没有维度、分值和证据。
- 未先断言 `job_family`，就直接套用 BD 或 MKT 评估框架。

## Verification（强制验收清单）
宣称“扫描完成”时，必须同时满足：
1. 输入源、岗位序列（`job_family`）、北极星指标、JD（若有）已显式记录，未知项必须标记 NULL。
2. 第一阶段已完成岗位门禁断言：只能是 `BD` 或 `MKT`，且已匹配到对应能力模型 Prompt。
3. 面试官 / 候选人话轮已完成物理剥离，且核心证据只从候选人话轮中抽取。
4. 每条高价值 STAR 证据都附带秒级时间戳。
5. 零信任质检至少包含：逻辑盲区、基准漂移、证据不足项、待补问题清单。
6. 最终结论必须同时包含：
   - 业务能力：仅允许 `[不推荐, 中性, 强推荐, 不可错过]` 四选一；
   - 字节范（ByteStyle）打分：必须有维度分与简要解释。
7. 报告必须含：视觉化雷达图、SWOT、Day 30/60/90 预演。
8. 正式输出开头必须先回显：`> 当前按 XX 岗位能力模型执行深度扫描。`

## Defaults（合规默认值）
- 默认分析语言：`zh-CN`
- 默认允许的岗位序列：`BD / MKT`
- 默认 STAR 证据优先级：`Action > Result > Task > Situation`
- 默认结论置信状态：`已证实 / 高概率 / 待验证`
- 默认雷达维度：业务理解、结构化拆解、数据敏感度、推动力、协同影响力、学习迭代力
- 默认 ByteStyle 评分维度：始终创业、多元兼容、坦诚清晰、求真务实、敢为极致、共同成长
- 默认缺失值占位：`NULL`
- 默认业务能力枚举：`不推荐 / 中性 / 强推荐 / 不可错过`

## Runtime Assertions（运行时物理熔断）
- 执行前必须运行 `scripts/validate_output.py`，对最终 JSON 做结构校验、岗位路由校验与结论枚举校验。
- `scripts/validate_output.py` 内置 `JOB_FAMILY_PROMPT_ROUTES`：`BD -> prompts/bd_model.md`、`MKT -> prompts/mkt_model.md`。
- 若缺失 `input_alignment.job_family`、枚举越界、岗位路由找不到 Prompt、ByteStyle 维度缺失、或 STAR 证据无时间戳，必须 `raise` 并熔断。
- 若输入中缺少 transcript source，也必须 `raise` 并拒绝继续分析。

## 输入定义
### 必填输入
1. 录音链接 / 飞书妙记链接 / 可解析逐字稿
2. `job_family`（仅允许 `BD` 或 `MKT`）

### 可选输入
1. 业务北极星指标（如：GMV、可售商家数、达人开播率、留存等）
2. JD / Role Expectation
3. 面试轮次、岗位级别、市场范围（UK/EU/JP/Global）

## 五步工作流
### 1. 岗位门禁断言
- 第一步必须先提取并断言 `job_family`。
- 若岗位描述、JD、输入维度与 `job_family` 冲突，立即输出“岗位-能力模型错配”并熔断。
- 不允许靠历史上下文猜岗位，也不允许在错配状态下继续补分析。

### 2. 岗位能力模型路由
- 当 `job_family=BD` 时，强制加载 `prompts/bd_model.md`。
- 当 `job_family=MKT` 时，强制加载 `prompts/mkt_model.md`。
- 两套模型不得混用；若路由表中不存在对应项，立即抛错。

### 3. 输入定义
- 识别输入来源、语言、时长、岗位语境。
- 若缺少业务北极星/JD，不得脑补，统一标记为 `NULL`，并在结论中提示“结论置信度下降”。

### 4. 物理剥离与锚点对齐
- 分离面试官与候选人。
- 优先抽取带数字、动作、结果的 STAR 证据。
- 每条证据必须挂载秒级时间戳，并标注与哪项能力维度关联。

### 5. 零信任质检与资产交付
- 检查逻辑盲区：是否只讲结果、不讲动作；是否只讲个人贡献、不讲协同约束。
- 检查业务口径漂移：候选人的成功定义是否与当前岗位北极星/JD 对齐。
- 标注证据密度不足项：哪些能力判断仍停留在“感觉像”。
- 输出候选人能力雷达图（建议 6 维：业务理解、结构化拆解、数据敏感度、推动力、协同影响力、学习迭代力）。
- 输出 SWOT。
- 输出 Day 30/60/90 预演。
- 输出最终结论：
  - 业务能力：`不推荐 / 中性 / 强推荐 / 不可错过`
  - 字节范（ByteStyle）打分：依据价值观维度逐项评分并给出总结。
- 在最终 JSON 对应的说明性开头，必须先回显：`> 当前按 XX 岗位能力模型执行深度扫描。`

## 输出结构建议
1. 候选人概览
2. 输入对齐卡（录音/妙记/job_family/JD/北极星）
3. STAR 证据墙（带时间戳）
4. 能力雷达图
5. 零信任质检
6. SWOT
7. Day 30/60/90 预演
8. 最终结论（业务能力枚举 + ByteStyle 打分）
9. 追问建议
