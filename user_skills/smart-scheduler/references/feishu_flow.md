# 飞书操作主干流程说明 (Feishu Flow)

本 Skill 强制采用“查-锁-建”串行逻辑。

## 核心红线：严禁自动预定

- **先盘后建，严禁越权**：在用户明确给出具体的时间段之前，本技能无论如何**只能处于排查与查询模式**。即使找到了可用的时间交集，也必须先将推荐的 2-3 个时段输出给用户，等待用户的显式确认。
- **时段偏好策略**：推荐时段应**优先选择下午时段**（如 14:00 以后），**尽量避免大清早**（如 09:00）的时段，除非用户有明确指示或下午已无任何空档。
- **接口调用限制**：绝对禁止未经用户显式确认（如“选第2个”、“确认预定xx点”）擅自调用任何日历写入/预定接口（如 `batch_create_events.py`）！

## 1. 查 (Check)
- **输入**：参与人邮箱/ID、候选日期、时长（默认 30min）。
- **工具/方法**：
  - 获取所有参与人在候选日期内的日历日程。
  - 检查“尚浦中心6楼”相关会议室的空闲状态。
- **输出**：空闲时段列表。

## 2. 锁 (Lock & Confirm)
- **机制说明**：这里的“锁”是指在正式创建前，必须暂停并向用户展示最终约定的所有信息。
- **确认点（必选项）**：
  1. **时间**：例如 2026-04-01 10:00 - 10:30。
  2. **参与人**：完整列举，确认无漏选。
  3. **会议室**：明确询问“是否确定预定：尚浦中心6楼 会议室？”。
- **注意**：
  - **用户不确认，严禁创建**。
  - 如果用户修改信息，需返回“查”阶段重新核对。

## 3. 建 (Create)
- **强制约束**：
  - 必须包含 **Idempotency Key**（由 `scripts/generate_idempotency_key.py` 生成），防止网络重试导致重复创建。
  - 禁止包含视频会议链接。
- **操作逻辑**：
  - 调用创建日程接口。
  - 获取 `calendar_event_id` 及其 `app_link`。

## 4. 通知 (Notify)
- **发送渠道**：向参与人或指定的群聊发送消息。
- **格式要求**：
  - **严禁发送**：视频会议链接、无关联的详情说明。
  - **必须发送**：卡片通知、直接跳转日历的直达链接。

---

## 异常兜底：生成忙闲矩阵表格
如果查不到全员空闲的时段：
1. **算法**：调用 `scripts/suggest_timeslots.py` 寻找 3 个候选时段（例如按冲突人数从少到多排序）。
2. **本地 xlsx**：调用 `scripts/build_availability_xlsx.py` 生成文件。
3. **飞书 Spreadsheet**：调用 Lark MCP 工具将本地 xlsx 上传并转换为 Spreadsheet。
4. **输出**：返回表格 URL 以及 3 个建议给用户，并说明：“未找到全员空闲，已为您生成忙闲矩阵表格 [URL] 供决策。”
