# extraction-playbook

## 1. 候选待办识别口诀

按“**动作 + 责任 + 时点/影响**”三连看：

1. **动作**：出现推进语气、补材料要求、明确下一步。
2. **责任**：能定位到人、角色、团队、双方或相关负责人。
3. **时点/影响**：存在 DDL、阶段节点，或不做会明显影响主线目标。

满足 2 项以上即可进入候选池；满足 3 项时优先保留。

## 2. 评论区纳入口径

以下评论默认纳入待办候选：

- “辛苦补 2 个 case”
- “给一下当前毛利情况”
- “这里看下谁负责”
- “补 3 条示例链接”
- “会前对齐一下方案”

以下评论默认不纳入：

- 纯感叹、纯情绪表达
- 对已完成内容的确认性反馈
- 不形成下一步动作的闲聊补充

## 3. Owner 标准化优先级

1. 正文中的中文实名
2. 评论中的实名 / 可解析 @ 提及
3. 角色名（如业务侧、物流侧、双方）
4. `待确认`

禁止顺序：邮箱、open_id、纯 IM 标识直接落入最终文档。

## 4. DDL 标准化

- 明确日期：保留原日期或转成 `YYYY-MM-DD`
- 粒度为“下周 / 本月底 / 会前”：仅当能结合上下文锚定时转成具体日期
- 无法锚定：统一写 `待确认`

## 5. 合并主线规则

多个文档都在推进同一主线时：

- 合并为一条主任务
- 来源列保留多文档引用
- 在事项描述中保留“补充了什么增量信息”

## 6. P0/P1/P2 快速判定模板

- **P0**：阻塞主线 / 明确 DDL / 跨团队承诺 / 预算或目标对齐
- **P1**：明确行动项，重要但不阻塞，近期推进
- **P2**：补充材料 / 调研 / case 收集 / nice-to-have
